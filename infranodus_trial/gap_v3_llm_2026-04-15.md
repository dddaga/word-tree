- step265: K=4 at N=4096 with ΔW proj — Tier-2 running

**What's missing:** The complete winner stack (ΔW rot + aug + K=4) at N=4096 has NEVER been tested as a unit. step266 attempted it but hit 23.21% at ep1 — script crash (likely config wiring error or the rotation+aug+K4 combo broken at N=4096).

**Why it matters:** step235's 97.30% was at N=2048. step266's failure means the N=4096 record (97.71%) is NOT the "all winners" config — it's an incomplete run. The actual all-winners combo at N=4096 could match or exceed the D=64 project best (97.86%).

**Specific test:** step267 — N=4096, K=4, ΔW rot, aug, Tier-2. Debug step266 crash first (check conn_hh dimension mismatch with K=4 at N=4096). Base on step265 (when done) + step729 results.

## 4. Contradictions / Tensions

### T1 — K=4 wins or ties depending on N and measurement scale
- step263 (N=4096, T1, seed=42): K=4 wins **+0.97pp** strongly
- step263 seed=43 running: will it replicate?
- step262 (N=2048, T2, 3 seeds): K=4 **+0.02pp** (tie)
- step264 (N=1024, T1, 2 seeds): K=4 **+0.05pp** (marginal)
- **Resolution needed:** N-dependent story is coherent (K=4 wins more as N grows due to over-smoothing hypothesis), but the step263 seed=43 result is decisive — if it replicates +0.97pp, paper claim is solid. If not, the N=4096 win was noise.

### T2 — step266 crashed: 97.71% record is from which exact config?
- The CLAUDE.md header says "97.71% at ~70K params" from step266 "ΔW rotation + augmentation"
- But the step266 JSON shows top1_best = 23.2% at ep1 (crashed/dead)
- The 97.71% number must be from a different config/seed not yet in results/ — either from a recent unreported run or a misattribution
- **Critical:** before paper, confirm exactly which script/config produced 97.71% and log it properly.

### T3 — Deep supervision killed (step521) but intermediate routing IS validated (step231)
- step521: ALL deep supervision configs −5.5pp (88.76-89.20% vs ref 94.75%)
- step231: iterative routing accuracy monotonically increases K=0→5 (0.09 to 0.92)
- **Tension:** step231 says each K_iter adds value, but step521 says adding loss at intermediate K_iters destroys performance. Resolution: supervision at K_intermediate constrains the routing to be "locally good" before it's ready, collapsing the refinement. The trajectory's value is in the FINAL state, not intermediate states.

### T4 — AH described as "static" but ΔW proj is "input-dependent"
- 2026-04-15 correction confirms AH is W_pos-only (static post-training)
- ΔW proj uses Z_nb (activation-dependent at inference)
- **Tension for paper:** The paper previously may have claimed "AH provides input-dependent routing" — must be corrected throughout manuscript. AH = learned static suppression; ΔW proj = actual input-conditional gate. Two mechanisms, different roles.

### T5 — Param count discrepancy (34,976 vs 67,744) unresolved
- bench_step810 reports SGNNET = 34,976 params
- training step199 reports 67,744 params
- Difference ≈ 32,768 — likely K_in=25 or K_in=50 seed projection matrix (N×D or similar)
- **Paper risk:** If left unresolved, reviewers will catch the inconsistency and attack efficiency claims.
