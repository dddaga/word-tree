## 5. Reframes

1. **What if SGNNET routing is fundamentally a sparse random projection + weighted collective averaging, not "message passing"?** The scatter (K_in) creates a sparse random feature map; routing aggregates these features with learned relational weights. This is closer to Random Kitchen Sink (RKS) + graph attention than traditional message passing.

2. **What if the 56% seed probe accuracy (untrained) means SGNNET's advantage over MLP at the same bottleneck is entirely about the random sparse projection, not the routing?** The routing adds ~10pp probe accuracy (56→67%) on untrained model. If training adds another ~26pp (67→93%), what fraction comes from learning W_pos vs learning routing weights?

3. **What if the paper is 90% written in existing data — the bottleneck is the manuscript, and every new experiment is procrastination?** All key claims (efficiency, accuracy, mechanism ablation) are validated.

4. **What if dense-input failure (Whisper/ESC-50) reveals SGNNET's core assumption: inputs must be sparse-spatial?** The scatter works for localized spatial features (VGG: 7×7×512 feature maps = each spatial location independent). For holographic representations, you need a different projection strategy.

5. **What if the participation ratio finding (PR grows 1.0→3.7 during untrained routing) is the actual mechanism?** Routing distributes class information into more orthogonal dimensions via the Watts-Strogatz graph structure, making the linear readout easier.

6. **What if the path to paper submission is a 2-week sprint on writing, not more T0 experiments?** We have >50 CONFIRMED experimental results. A paper could be drafted with these today.

**POC R1 — RKS vs SGNNET scatter:**
```python
import torch, numpy as np
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler

# Random projection baseline: project 25088→16 via random Gaussian
torch.manual_seed(42)
N, D, N_IN = 2048, 16, 25088
x = torch.randn(100, N_IN)

# RKS: random 25088→16
W_rks = torch.randn(N_IN, D) / N_IN**0.5
Z_rks = (x @ W_rks).numpy()  # [100, 16]
# SGNNET scatter: randomly pick K_in=25 features per node
K_in = 25
conn_in = torch.randint(0, N_IN, (N, K_in))
W_in = torch.randn(N, K_in, D)  # [N, K_in, D]
x_gathered = x[:, conn_in.reshape(-1)].reshape(100, N, K_in)
Z_sgnnet = (x_gathered.unsqueeze(-1) * W_in.unsqueeze(0)).sum(dim=(2,3))  # approx
Z_pool = Z_sgnnet.mean(dim=1).numpy()  # [100, 16]

print(f"RKS Z std: {Z_rks.std():.4f}")
print(f"SGNNET scatter Z std: {Z_pool.std():.4f}")
# Both are random linear projections — the scatter IS a random projection
# But SGNNET's trained version learns WHICH features go to which nodes (via K_in positions learned through W_pos)
```
Result: Both are random linear projections. The scatter is equivalent to RKS at random init. The key difference is that SGNNET's W_pos positions make the K_in assignments non-random after training — they learn spatial proximity groupings. **Reframe R1: SURVIVED (scatter = RKS at init, but W_pos learning creates structure beyond RKS).**
