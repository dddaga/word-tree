# Training Guide

## Overview

All active training happens in `vgg_training/`. The pipeline has two eras:

- **Runs 1–9:** Used a shared `vgg_training/training.py`. Config passed as CLI arg.
- **Runs 10+:** Each run has its own `training_runs/runN/training_runN.py` (copied from the previous run's script and modified). This makes every experiment fully self-contained and reproducible.

---

## Creating a new experiment (run10+ standard)

**Every new run requires these artifacts before training starts:**

### 1. `training_runs/runN/config.yaml`

Full config — not just the delta from the previous run. Add a comment block at the top:
```yaml
# runN — <one-line description>
# Goal: <what you're testing>
# Base: runM (<the run this is based on>). Change: <exactly what changed and why>
# Evidence reference: <analysis script or notebook that motivated this change>
```

### 2. `training_runs/runN/training_runN.py`

Copy the previous run's training script and update:
- All path references (`run10` → `run12` etc.)
- Top docstring to describe the actual change
- Any model-class assertions that are version-specific

Never modify a completed run's training script.

### 3. EXPERIMENT_QUEUE.md entry

Add a row to the Queue table in `vgg_training/learnings/EXPERIMENT_QUEUE.md` before launching. Fields: Run, Status, Hypothesis, Key delta, Expected result.

### 4. Pre-experiment diagnostic (if applicable)

If the run is motivated by a diagnosed problem (e.g. gradient starvation, activation collapse), run and save the diagnostic analysis first. Place the script in `vgg_training/` (e.g. `gradient_starvation_analysis.py`). Reference it in the config comment and in the EXPERIMENT_QUEUE entry.

### 5. Triple-write the design discussion

After designing the run but before launching, write to all three knowledge layers:
- **Graphiti:** `mcp__graphiti__add_memory(...)` with `group_id="sudarshan"`
- **LEARNINGS_p*.md:** Append a dated design entry
- **`learnings/concepts/`:** Update or create the relevant concept page

## Launching training

```bash
cd /Volumes/T9/IndraAstra/sudarshan/word-tree/fixed_io_nodes/vgg_training
tmux new-session -d -s runN \
  '/Volumes/T9/IndraAstra/sudarshan/.venv/bin/python -u \
   training_runs/runN/training_runN.py training_runs/runN/config.yaml \
   2>&1 | tee training_runs/runN/train.log'
```

**Check status:** `tmux ls`  
**Attach:** `tmux attach -t runN`  
**Detach:** `Ctrl-b d`

The Mac Mini runs one training session at a time (MPS device). Do not launch a new run until the current one finishes or is explicitly stopped.

## Data

Pre-processed imagenette-10 VGG16 features stored as tensors:
- `vgg_training/data/imagenette_train_data.pt` — `{data: (N, 25088), label: (N, 10)}`
- `vgg_training/data/imagenette_val_data.pt` — same format

Labels are one-hot encoded (shape `(N, 10)`). For CrossEntropyLoss, either pass directly (PyTorch ≥1.10 soft-label support) or use `label.argmax(1)` for integer targets.

Data was generated by `prepare_dataset.py` using a frozen VGG16 feature extractor. Do not regenerate unless the dataset version changes.

## Shared code changes

When adding a new config parameter to `native/layer.py` or `core/custom_functions.py`:
1. Default to the existing behaviour (backward compatible — old configs must still work).
2. Add the parameter to `documentation/architecture.md` config reference table.
3. Note the addition in the run's config.yaml comment and in EXPERIMENT_QUEUE.md.
4. Write to all three knowledge layers (Graphiti, LEARNINGS, concepts).

---

## Evidence tagging rules

All findings must carry one of:
- **CONFIRMED** — clean ablation, exactly one variable changed, control run present
- **HYPOTHESIS** — post-hoc explanation, confounded experiment, or indirect evidence
- **STALE** — confirmed on a prior architecture that has since changed significantly

Post-hoc explanations are always HYPOTHESIS. Never promote to CONFIRMED without a controlled experiment.
